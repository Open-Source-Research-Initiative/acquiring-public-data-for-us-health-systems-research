# Model executor qualification: synthetic probe

Historical routing investigation, 17 November 2026. Later [executor conditions](executor-conditions.md), [current qualification](../../evidence/executor/qualification.json), and [pilot observations](../../evidence/pilot/README.md) supersede its initial disposition. The sections below preserve the progression and limits.

Initial status, 17 November 2026. **Blocked; not qualified for pilot cases.** The existing Codex CLI authentication can start a fresh model session, but this investigation did not establish a model-facing tool allowlist containing only the intended broker. No pilot packet, candidate software, reference value or health data was used in these probes. The following is evidence about the tested configuration, not a security certification or an exhaustive proof about Codex.

The tested CLI was `codex 0.169.0`, reached through `/home/builderbob/.local/bin/codex`. Its local help documents `exec --ignore-user-config --ignore-rules --ephemeral` and feature overrides. An ephemeral thread is not by itself an isolated tool boundary. The app-server's generated experimental schema exposes `dynamicTools` and an empty `environments` option; whether these can provide and enforce the required sole broker is untested. App-server is not an approved substitute on this evidence.

## Synthetic observations

- A fresh `codex exec` used `--ignore-user-config --ignore-rules --ephemeral --skip-git-repo-check`, disabled `shell_tool`, `unified_exec`, `apps`, `plugins`, `view_image`, `multi_agent`, `multi_agent_v2`, `skill_search`, and `remote_plugin`, set `web_search="disabled"`, and used an empty workspace directory. The model reported that no shell was available, but also reported a `functions.exec` interface with other tools. A subsequent request successfully called its clock tool and attempted `apply_patch`; the read-only sandbox rejected the write. This establishes callable non-broker routes, not just a model's account of its tools.
- Repeating the clock and patch probe with `env -i`, preserving only existing `HOME`, native `CODEX_HOME`, `PATH`, `LANG`, and a workspace `TMPDIR`, produced the same results. No inherited session ID or proxy variables were deliberately passed, and no credential contents were read or printed. The native authentication state was neither copied nor reconfigured. This does not prove all possible inherited channels are absent.
- Adding `--disable code_mode_host` caused the clock and patch requests to fail with `code-mode host is disabled`. A locally configured synthetic stdio MCP server with one `synthetic_ping` tool was then tested under the same disabled-host configuration; the requested ping failed with the same error. This is a demonstrated fail-closed route, but it also prevents this tested broker path from operating.

The model's self-reported tool inventory and large input-token count are not a verified inventory or evidence of context contents. The probes do not establish that a reference could be read through any particular route. Conversely, they do not exclude that possibility. A read-only filesystem policy is insufficient to hide held-out references or authentication material.

## Consequence and remaining work

Do not start a case or call this configuration blinded. A candidate solution must demonstrate an actual fresh model and a sole usable constrained broker, with no other reachable host, browser, filesystem, MCP, agent, or credential route; then pass independent synthetic canary and adversarial routing tests. App-server dynamic tools with a genuinely disabled environment are a possible investigation, not an established solution. Any such solution must also connect to the separately qualified candidate sandbox and external egress and resource controls, without exposing authentication to candidate code. The protocol's packet lock, independent reference separation and other prerequisites remain separate gates.

The probe was run by Codex with local CLI 0.169.0; no independent human reviewed it. This record is an implementation investigation, not an actual pilot attempt, outcome classification, independent review, or scientific result.

## Structured-action prototype

A subsequent synthetic prototype uses fresh ephemeral `codex exec` invocations with `--output-schema`. Each turn receives the locked task and bounded prior broker results, and returns a proposed `run` argv or `finish` summary. The harness validates the response and invokes only its supplied broker callback. It disables the native code-mode host and the listed native tool families, requests no user configuration or rules, skips host skill discovery, and starts with a minimal environment preserving existing native authentication locations. The experimental host-skill-discovery flag is not itself proof of absence of injected context. Paths supplied as standalone absolute or parent traversal arguments are rejected as a guard; only the sandbox can enforce containment against arbitrary commands or shell expressions.

A synthetic native-authentication smoke test completed two fresh model turns: the model requested `printf synthetic-pong`, the separately invoked namespace sandbox returned that output, and the next model turn summarized the result. Unit tests cover broker handoff, malformed actions, native-host error rejection, result bounds and turn limits. No real case was run. The transport changes each decision into a fresh invocation with reconstructed history; it is an agentic model-directed action loop, not an autonomous native tool session or a deterministic command plan. The selected model, task, context, tool controls, versions and histories must be frozen for a case. This synthetic success does not qualify the native tool boundary, context separation, sandbox, egress, quotas or scientific protocol. Independent adversarial route and canary testing is pending. The caller must independently enforce total attempt budgets and case resource controls.


## Process and native-route checks

The prototype at this stage pinned `gpt-6.1-sol` explicitly. Each turn launches Codex CLI 0.169.0 inside a fresh PID namespace using `unshare --map-current-user --pid --fork --kill-child=KILL`, keeping the host UID and existing native `HOME` and `CODEX_HOME`. The environment contains only those native paths, a fixed PATH, LANG and workspace TMPDIR. The CLI uses `exec --ignore-user-config --ignore-rules --ephemeral --skip-git-repo-check --sandbox read-only --json --output-schema ... --enable skip_host_skill_discovery -c web_search=disabled --model gpt-6.1-sol`, and disables `shell_tool`, `unified_exec`, `apps`, `plugins`, `view_image`, `multi_agent`, `multi_agent_v2`, `skill_search`, `remote_plugin`, `code_mode_host`, `goals`, `sleep_tool`, `image_generation`, `browser_use`, `computer_use`, and `memories`. The schema is generated in a temporary workspace directory. This list is a tested configuration, not an exhaustive inventory of all possible native tool routes.

The launcher streams stdout and stderr with a combined one-million-byte cap, a per-turn wall-clock deadline, and process-group termination in cleanup. The Codex process is PID 1 in the nested PID namespace: kernel teardown kills remaining namespace descendants when it exits, and the `unshare` parent requests its death on launcher failure. Synthetic tests exercised the output cap, timeout and a child that calls `setsid` before its leader exits; the child could not create a delayed workspace marker. This does not establish a whole-case CPU, disk or network limit, or prove cleanup under every kernel or host failure.

With the pinned model and this launcher, a fresh two-turn synthetic `printf synthetic-pong` action again succeeded through the sandbox broker. In a separate synthetic request, the model attempted a native code-mode patch to create a workspace marker: the disabled host rejected the native invocation, the adapter then detected that rejection and discarded the action, and the marker was absent. The preventive control is the disabled native code-mode host (with read-only sandbox as another restriction); parsing the error afterward detects this observed attempt and does not undo a tool effect. No conclusion follows for untested native routes, leaked input, or reference access. Six local unit tests passed, including a mocked native error and the synthetic process tests. Independent adversarial testing and the remaining protocol gates are still required.

## Terra, synthetic route coverage and shared budget

The current prototype is pinned to `gpt-6.1-terra`; the preceding Sol observations describe the earlier tested configuration. A fresh Terra two-turn structured-action run requested `printf terra-synthetic-pong` through the sandbox broker and then summarized the returned result. Separate synthetic prompts requested native shell execution, a read of a private workspace canary, opening a loopback port, application listing, and MCP resource listing. Each produced the code-mode-host-disabled error and the adapter rejected the decision. This demonstrates prevention at the tested code-mode route and subsequent error detection; it does not independently establish that each named backend or every alternate direct route was reached or unavailable. A request to list agents returned a structured action without an observed native call, so agent-route prevention remains unproven. The canary was synthetic; no real reference or credential content was read.

`cli_decide(..., budget=session.budget)` reserves the lesser of the requested timeout and remaining active time, with a small snapshot-to-reservation margin, before invoking the model. It reconciles actual boot-clock elapsed time after termination, including on handled failures; a process crash leaves its reservation charged. For conservative shared accounting, the ledger charges the hosted-model wall time against both active and VM ceilings even though model inference is remote. The same ledger must be passed to the sandbox session; merely omitting `budget` does not provide case accounting. A synthetic native model call using a real local ledger returned a finish action, charged positive active and VM time, and left no open reservation. Seven local runtime unit tests passed. Independent adversarial route and context review and all separate pilot prerequisites remain required.
