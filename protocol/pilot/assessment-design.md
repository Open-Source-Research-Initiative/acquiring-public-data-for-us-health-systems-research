# Pilot assessment design — proposed, no fixtures prepared

17 November 2026. This public design covers the eight currently proposed cases, not locked tasks, executed workflows, publisher payloads or results. It contains no selected source records or expected values. Apply the current case JSON and [protocol](../../protocol.md); if a case changes before lock, revise this design prospectively. All eight may prove unassessable. The pilot progression rule still requires at least three **actual assessable comparisons** across at least two source families, independently reviewed; preparation alone does not meet it.

## Common assessment procedure

Before execution, an assessor who cannot use the evaluated program's output fixes each task's source identity, exact request and time window, eligible source grain, reference method, fields, canonicalization, missingness and scope. Capture publisher evidence independently of the evaluated workflow, within applicable access and resource rules. Where a source permits, use an independently observed publisher copy or API response and record provenance, source URL, request, timestamp, release/revision and locally calculated digest. Do not assume a publisher checksum exists. A hash identifies retained bytes, not publisher truth, completeness or historical availability. If evidence or permissions are absent, record the barrier; do not invent expected data.

Choose future fixtures **from the reference source alone before seeing output**. Freeze an assessor-only seed and deterministic stable-key sorting before examining candidate rows. Propose up to six unique units per case: up to three general source rows, one boundary/time or geography row, one missing/suppressed-value row and one documented duplicate/linkage edge row where applicable. Choose reproducibly within each available stratum; record unavailable strata and actual counts rather than fabricate them. Preserve duplicate multiplicity. This is purposive bounded checking, not a representative accuracy estimate or proof of complete acquisition. A legitimate empty result gets a separately corroborated empty-query check if possible; no matching evidence means unknown. Do not alter selected workflow parameters to obtain a preferred fixture.

In the sealed assessment packet record selected keys, source excerpts/values, original types, documented units, derivation and comparison rules, plus evidence. Prepare a separately authored checker with at least a known-matching reference fixture and mutated controls for a changed key/release, altered value and missing-versus-zero; retain actual test outcomes. These checks validate limited checker behavior, not truth. Distinguish source-derived fixtures independently prepared from the evaluated implementation from **independent human review**: a second qualified human must audit reference and classifications before such a claim. An agent or a separate execution context is not a second human.

For rolling sources, independently capture the same parameters and relevant fields near the workflow's acquisition event, including a before and after observation where feasible under the protocol. Record actual times, source versions, pagination and revision/issue metadata. Match to the input actually acquired where observable; A/B equality alone does not prove no intervening update. If observations differ, the input is hidden or the matched source revision cannot be established, the disputed comparison is unknown/non-comparable. A current snapshot can be verified within its bounded observation window without an immutable release; do not call it a frozen historical release. Prevent the executor accessing reference-derived keys, values, fixtures, results or feedback. Lock timestamped output and primary log before unsealing. Record custody, access, accidental disclosure and any later assisted phase; file labels alone are not access control.

Common canonicalization: compare declared source keys as strings (preserve leading zeroes), map documented field names explicitly, and sort by complete key only for order-insensitive tables. Preserve types, duplicates, dates, units and missing/suppressed/zero distinctions; normalize line endings and Unicode only if predeclared and lossless. Numeric equivalence requires a source-precision-based tolerance fixed before output inspection; otherwise compare exact represented values. Report byte and semantic equality separately. No later choice of tolerance, subset or source may rescue a mismatch.

## Case-specific checks

| Case and target | Source identity, grain and prospective comparison | Scope, viability and limitations |
|---|---|---|
| **01 HCRIS downloader** | CMS hospital 2552-96/2552-10 fiscal-year archives for all default requested years; record publisher revision/update date, form, source URL and archive/member identity independently. At report grain compare report identifier, provider, fiscal start/end and status; for selected numeric records compare report/worksheet/line/column and value, preserving absent versus zero. [CMS HCRIS](https://www.cms.gov/data-research/statistics-trends-and-reports/cost-reports) and form-specific dictionary govern meanings. | Full requested 1996–2024 collection includes both forms in overlap years. Samples verify only those extracted facts; full acquisition needs archive/member inventory and evidence for every requested file, not sample agreement. Historical revisions, HTTP, storage and independent access may prevent assessment. A report is not automatically a hospital-year or all operating hospitals. |
| **02 NPPES API client** | [CMS Registry API](https://npiregistry.cms.hhs.gov/api-page), current snapshot, same version and documented exact number query. Compare response status, result count, NPI, enumeration type and fields actually present in a matched independent observation. Treat a verified empty response as empty; no evidence that it should be nonempty. | One bounded query, not whole registry. Input number is a published example, not a guaranteed provider. Source drift, inaccessible documentation, rate limits and an empty result without comparator can make it unassessable. |
| **03 CDCPLACES** | [CDC 2025 county dataset](https://data.cdc.gov/500-Cities-Places/PLACES-Local-Data-for-Better-Health-County-Data-20/swc5-untb/about_data) and [dictionary](https://data.cdc.gov/500-Cities-Places/PLACES-and-500-Cities-Data-Dictionary/m35w-spkz/about_data): 2025 release plus dataset revision and observation time. Compare county ID, measure ID, value type, survey year, value, units and interval at the complete documented row grain. Include absent/suppressed values if present; 2025 release year is not necessarily survey year. | Default is unfiltered county query. Sample comparison is bounded; pagination and complete-source inventory are needed to assess the full returned scope. CDC [release notes](https://www.cdc.gov/places/current-release-notes/) identify measure/geography exceptions. Estimates are modeled, not patient observations. Availability, version match and transfer scope untested. |
| **04 cdcfluview WHO/NREVSS** | CDC [FluView](https://www.cdc.gov/fluview/overview/) and independently captured matched national snapshot: season, reporting week, laboratory category and reported test measure. Keep clinical and public-health laboratories distinct; assess dates and missing fields against matching source definitions. | Default requests all available seasons. A handful of matched rows cannot prove full coverage; no patient-case denominator follows from specimens. Old GIS endpoint and comparability with current CDC display are unresolved; changing releases can make assessment unknown. |
| **05 COVIDcast** | [CMU Delphi COVIDcast API](https://cmu-delphi.github.io/delphi-epidata/api/covidcast.html): fb-survey/smoothed_cli, state geography, from documented start date to metadata-derived latest date and latest issue. Compare source, signal, state key, time value, issue/as-of, value, and relevant metadata at matching snapshot. Do not substitute a later issue for the selected observation. | Default query spans many dates and states; selected checks do not establish completeness. Legacy service, source revisions, discontinued feeds and availability of matched observations are untested. |
| **06 EPHTrackR** | [CDC Tracking API documentation](https://ephtracking.cdc.gov/apihelp), measure 99, state stratification, default all available geography/time. Independently determine the applicable measure definition, output grain and units from metadata; compare measure, state, period, strata, estimate/value and missing/suppression flags at matching snapshot. | A measure number alone does not establish semantics or coverage. Anonymous access, current endpoint, metadata and comparable reference are untested; empty/suppressed values are not zeros. Samples do not establish all geography/time returned. |
| **07 countyhealthR** | [2024 CHR&R Zenodo source](https://zenodo.org/records/18331995) and separately referenced metadata record [18157793](https://zenodo.org/records/18157793): selected documented `get_chrr_measure_data(geography = "county", measure = "premature death", release_year = 2024)` example. Match release and archive identities, county identifier, measure ID, data period, value, unit and missing/suppression/status fields when documented. Preserve metadata-to-data join and any legitimate multiple rows. | Measure-filtered output may require downloading full annual tables; assess returned scope and byte-transfer scope separately. Zenodo record mapping, archive version, metadata schema and any equivalence to the published release remain to be confirmed; source-derived agreement does not validate mortality estimates. |
| **08 PricePortal NPPES lookup** | Current NPI Registry organization lookups after the CMS Hospital General Information prerequisite; retain both source identities, snapshot times, input hospital identifier/name/address and registry request/response. Compare selected input records, request parameters, NPI-2 results and returned match fields against independent same-window publisher observations; separately inspect fuzzy-match rationale and unmatched/ambiguous cases. | Current NPPES lookup is the selected workflow; do not assess the superseded Medicare fee-schedule task. Correct response extraction does not prove hospital-to-NPI linkage. Optional crosswalk presence, mutable registry, rate limits and `/data0` workspace-backed isolation may block a comparable attempt. It shares NPPES upstream with case 02 and is not an independent source family. |

For each case, report the number and kind of source strata available, selected and actually compared, plus unmatched and unknown counts. Record independently established mismatches, barriers and non-comparable results separately. Full-release verification needs independently supportable completeness evidence; otherwise state the narrower verified extraction or leave acquisition unverified. No author output means bounded source-to-output fidelity cannot be described as reproduced author output. Neither reference concordance nor an exit code certifies substantive research fitness.
