# Prospective amendment: pilot cases 02–08

17 November 2026. The human lead's current authorization permits routine runtime completion and attempts of the seven remaining selected pilot cases. This prospective amendment supersedes the case 01-only launch restriction in [executor conditions](executor-conditions.md) for cases 02–08, subject to case-specific technical qualification and locks. It does not authorize the main evaluation or establish independent human review. The original case 01 primary, its conditions, outcomes and evidence remain immutable; nothing here repairs, replaces or reclassifies that attempt.

## Preparation, locks and resources

Common runtime preparation is outside each timed attempt. Known bytes of shared preparation artifacts are conservatively pre-debited to each case's resource record as applicable. Historical preparation metadata, transfer quantities or time that cannot be reconstructed are unknown and must be disclosed; they are not zero. Before each attempt, retain the actual runtime and dependency inventory, source revision and integrity, task and capture procedure, network conditions, packet hashes and qualification results. A setup or qualification barrier is retained as a case disposition, not grounds to replace or silently alter the selected case.

The case disk allocation is at most 46 GiB for the shared input, executor and reference image, 46 GiB for retained regular-file outputs, and 8 GiB for read-only runtime and control material, totaling no more than 100 GiB. Logical output size and both primary and reference locks count. The existing network accounting definition and shared case ledger apply, including reference requests and conservative durable reservations. Preserve pre-debits and actual meter readings separately.

Each remaining case has the full prospective ceilings of three active hours, four runtime hours and six elapsed hours, with the other protocol limits unchanged. Record case start and end, preparation pre-debits, resource consumption and any measured overrun. The currently planned primary consists of one native invocation of the selected task, with no silent retry. The protocol's allowance of at most one justified transient retry or one later diagnostic repeat, but not both, remains subject to an explicit separately recorded decision; neither replaces the original outcome. Reference activities share the case limits. Preserve errors, partial outputs and failed capture as observed, distinguishing them from native execution outcomes.

## Runtime and task conditions

For the R cases, install the exact pinned candidate source first using `R CMD INSTALL` against offline staged dependencies rather than the draft `devtools` installation wrapper. Record dependency versions, omitted Suggests and any resulting limitation. This is environment preparation, not a source-code patch or a change to native task parameters. Preserve the exact case selection and native invocation, including full defaults; capture returned objects without changing their values or suppressing errors.

Case 03 and case 07 environments may issue a connectivity probe to `captive.apple.com`; declare this destination and the observed disposition in their locks and logs. It is not the health-data source and its result does not establish publisher availability.

For case 05, retain the selected legacy URL and installed wheel's URL-append behavior. Do not rewrite to another provider or endpoint. Disclose the blocked PyPI update check and distinguish it from the selected health-data request and its outcome.

Case 07's selected data are the 2024 release while its native metadata request uses 2025; retain and report that distinction rather than silently substituting metadata. Case 08's native task and prerequisites include California and Indiana as implemented; preserve both and document the clean-cache and optional crosswalk state. Its upstream hospital list and NPPES organization lookup are separate source observations.

## Reference and interpretation

Keep reference planning and capture separate from the executor and lock the primary output and log before assessment disclosure. Where only source metadata can be independently captured and no full independent oracle exists, describe it as metadata-only evidence. It cannot establish full acquisition, source-to-output fidelity or verified fidelity. Empty, inaccessible, blocked, partial and unresolved outcomes remain distinct, and no comparator is invented. Cases 02 and 08 share the NPPES source family; system counts are not independent source samples.

These conditions are prospective implementation records, not evidence that any case has run or passed. Record material deviations with their dates and reasons. Scientific claims, independent human assessment and any progression beyond feasibility remain subject to the [protocol](../../protocol.md) and human review.
