# Proposed provider and hospital cases: preparation notes

17 November 2026. The two cases are proposed for Cole Lyons and independent human review; no selection is locked and execution is not authorized. Review is based on live, read-only metadata and immutable source text. No candidate code was run and no health payload obtained. GitHub REST metadata/release calls returned **403 rate limit**; read-only `git ls-remote` supplied branch and tag pointers, and GitHub's release page and raw versioned source were inspected. The prior provider-data-tools fork is not selected; its fork lineage is irrelevant to the separate adesigns client except that they both access provider sources.

[PILOT-01](../cases/PILOT-01.json) selects HCRIS's sole documented downloader. CMS describes annual ZIPs with report, numeric and alphanumeric tables in its [cost reports documentation](https://www.cms.gov/data-research/statistics-trends-and-reports/cost-reports). The script's full default range includes both cost-report formats in overlapping years and deletes the archives. No safe storage, current HTTP reachability, completeness, rights or actual archive size has been established. A future assessor could separately capture matching publisher release identity, archive manifest and permitted byte receipts, then compare named extracted file membership and a small independent selection of fields. A same-input author output is not established. Full-range completeness would require a source inventory for every requested file and form/year; otherwise report bounded coverage or not assessable. Source availability or default transfer may preclude an attempt.

[PILOT-02](../cases/PILOT-02.json) chooses the NPPES client's single-number README example by the recorded deterministic rule. `searchByNumber` delegates to `search`, so the two README examples are parameters of one acquisition workflow; if reviewers decide they are distinct native workflows, re-enumerate and recalculate prospectively. The named number is a published example parameter, not a source observation or expected answer. It may return no result; do not change it based on a result. Publisher [API documentation](https://npiregistry.cms.hhs.gov/api-page) yielded no readable text through the browsing tool; the [CMS NPPES dissemination guidance](https://www.cms.gov/medicare/regulations-guidance/administrative-simplification/data-dissemination) offers contextual source information. Before execution, assess current API terms, safe access and whether an independent current-snapshot query with identical parameters can be retained. A separately controlled assessor could compare source response metadata, result count, returned identifier/fields and null handling against the locked client output; if no result exists, independently assess whether empty/null is the correct response and whether the implemented error path can be assessed, without classifying emptiness itself as failure. Snapshot drift, authorization and unavailable reference make comparisons non-comparable or unknown. It is a bounded query, not a census or license verification.

Separate execution-facing JSON files contain no expected records, reference-selected observations or checker answers. This design memo describes assessment method only; no sealed reference, benchmark response or fixture exists. Reference collection and independent human review are outstanding. A GPT-6 agent inspected repository documentation and source files and prepared these notes; no independent human review is claimed.

Sources inspected 2026-11-17: the versioned README, implementation and package paths linked in the JSON; GitHub repository releases and `git ls-remote` tag/HEAD metadata; CMS source documentation linked above. The GitHub API failure and CMS API page extraction failure are retained as unresolved limitations. Dates and tasks are prospective and must be rechecked at protocol lock. **Example selection update.** The protocol hierarchy uses a complete native default first, then a uniquely designated canonical quickstart, then a separate deterministic example seed. The pinned NPPES README has two eligible examples and no identified complete default or uniquely designated quickstart. Their sorted identifiers are `search-last-name`, `searchByNumber`; SHA-256 of `OSRI-health-data-pilot-v1|PILOT-02|example` is `e44fa9de4e2c185d326f0f66dff2723879f67f049ac38c90a2339b86f6a2bb28`. Its first 16 hex digits are `e44fa9de4e2c185d`; the resulting integer modulo two is one, selecting `searchByNumber`. The previous proposed method reused the workflow seed; it is superseded and happened to select the same method and documented parameter. No outcome or reference informed this selection.

**Configuration decision.** Immutable source pinning is coordinator-managed environment configuration under the lead's delegation. Freeze it consistently before execution. Installation of the NPPES library specifies version `1.0.6` and requires verifying its resolved source reference against the pinned commit; transitive dependency resolution remains to be frozen and reviewed. HCRIS checkout explicitly names its commit. Neither operation has been executed. A returned empty result can be a valid outcome; this single query does not establish full-registry acquisition.

**TLS safety correction.** The pinned [NPPESApi.php](https://github.com/adesigns/nppes-api/blob/2b6a830d608885dd3a814952fbf18575431b5cf5/src/AlbanyDesigns/NPPESApi/NPPESApi.php) uses `(int) $verifySsl === true ? 1 : 0` for `CURLOPT_SSL_VERIFYPEER`. Static inspection raises concern that the integer-to-boolean strict comparison disables peer verification even for the default constructor. The earlier statement that default TLS verification was retained was incorrect: only the default constructor is retained. This has not been runtime-tested. The global safety preflight must assess it before any authorized attempt; do not patch or silently mitigate the candidate. Empty client output or an error cannot independently prove that the publisher returned a valid empty response.
