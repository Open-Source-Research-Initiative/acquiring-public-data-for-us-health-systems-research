# Prospective amendment: diagnostics for pilot cases 06 and 07

17 November 2026. The human lead authorizes improved request/response tracing, investigation and correction of established proxy barriers, and one separately recorded diagnostic native repeat each for PILOT-06 and PILOT-07. The original primary attempts, their locks, logs, outcomes and major-claims review remain preserved. These diagnostics do not replace or reclassify those attempts, authorize the main study, or establish independent human review. The earlier six-hour observation windows have expired; observations from those windows do not become contemporaneous references for the diagnostics.

## Scope and accounting

Each diagnostic is a new prospective phase with its own empty workspace-backed directories, lock, start and deadline, and fresh durable resource ledger. It uses the same pinned candidate code, selected task and runtime as its original case, verified by hashes before launch. Record the exact configuration, proxy revision and qualification, input identities, timestamps, changes and deviations before the diagnostic. Preserve case 06's measure 99 and defaults and case 07's selected 2024 data and native 2025 metadata behavior. Do not patch candidate code, change task parameters or substitute sources.

Each diagnostic has ceilings of three active hours, four runtime hours, six elapsed hours, four CPUs, 16 GiB memory, 100 GiB disk and 20 GiB application request and response bytes. Start the elapsed clock at actual isolated setup. Installation, native execution and any independent reference work share that diagnostic's ledger and caps. Account for staged inputs using the existing conservative predebit and durable reservation rules; distinguish measured transfers from predebits and unknown historical quantities. The application-byte limit is not a total wire-traffic measurement. Retain actual readings, termination, any overrun and the reason for an incomplete operation. Apply and verify the existing isolated execution, aggregate storage, network, credential and resource controls before launch; stop with a typed blocked outcome if they cannot be established.

A diagnostic consists of at most one separately identified native invocation per case, with no silent retry beyond behavior already built into the pinned native code. Preserve setup, errors, partial outputs and capture failures. Implementation and transport probes are separately identified and recorded; they are not native workflow invocations or evidence of a completed workflow. Paired-request technical probes occur before the native diagnostics under their own newly declared engineering ledger, with their requests and resource use recorded there. Operations performed within a diagnostic phase, including reference and publisher requests, are charged to that diagnostic ledger. Synthetic qualification alone does not establish publisher or candidate behavior.

## Trace and policy qualification

The approved controlled HTTPS baseline remains in force: the inspecting proxy validates the publisher's upstream certificate and hostname, and the candidate sees the proxy's TLS peer. Retain that transport limitation. Record bounded request and response provenance, timing, authority, method, request-target and request-body SHA-256 digests and body byte count, status, byte counts and specific policy disposition sufficient to identify the rejected property. Retain no raw path, query or header values. The response trace hashes fully forwarded raw HTTP chunks and counts their bytes. upstream_eof records whether upstream EOF was reached; message_complete is null because framing is not validated. On a partial send exception, count_is_lower_bound is true. Avoid retaining credential values or unnecessary sensitive data. Credentials remain denied, as do unapproved destinations and bypasses. A proxy denial is a controlled-environment barrier, not by itself proof of publisher unavailability or candidate failure.

The original records did not retain the rejected property. Anonymous publisher-issued session cookies are a hypothesis, not an established cause. Establish the actual rejected property through trace and controlled qualification before any policy change. If the trace supports a cookie-specific correction, the allowance is limited to an exact previously publisher-issued cookie name/value pair returned to the same HTTPS host and port 443 within the session. The source session is anonymous in the sense that it uses no login or host credentials; that context does not prove the content of a cookie is anonymous. Keep at most 128 issued pairs of at most 4096 bytes each in ephemeral session state. The native client handles Path and expiry; the broker retains older issued pairs within that session and limit. Credentials and unrelated cookies remain denied. Qualify the exact policy using synthetic positive and negative controls, including origin isolation and credential denial, and exercise the native client multi-request behavior. Record the evidence, policy change and remaining limitations before the repeat. If the cause remains unresolved or a safe bounded correction cannot be qualified, retain the block and do not infer a successful correction.

## Reference and interpretation

Any independent diagnostic reference must be captured separately within that diagnostic's own six-hour window and shared resource budget, as close to the invocation as practical. Record request times, source identity, status and digest; matching windows alone do not prove matching revisions or complete source coverage. Preserve inaccessible, incomplete, mismatched and unresolved references as such. The existing metadata-only reference adapter remains in use. If source fixtures needed for a full comparison are unavailable, record a typed unassessable outcome. Retain the distinction between metadata-only evidence, returned-record agreement and complete acquisition. Case 07's data and metadata release distinction remains explicit.

Report diagnostic results separately alongside the original attempts and do not count them as replacement primaries. Conservatively, do not credit a diagnostic comparison toward the existing three-case/two-family progression gate without a prospective adjudication of the protocol's eligibility and independence requirements and independent human review. A successful diagnostic alone neither passes the gate nor approves the main evaluation. Record findings only after the relevant observation and assessment; retain the original major claims review and link any subsequent review without overwriting it.
